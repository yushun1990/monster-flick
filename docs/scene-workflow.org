#+TITLE: 场景协作流程

* 背景

小说创作不直接从 Canon 进入章节正文。

在正式章节之前，先通过讨论逐步落地具体画面（Scene）。

* 目录职责

- docs/ :: 世界观、人物设定、创作规则。
- scenes/ :: 已经通过讨论明确的具体画面。
- manuscript/ :: 最终进入章节的正式正文。

* 场景工作方式

一个场景不是正文草稿，也不是设定文档。

它可以保存：

- 最初灵感。
- 讨论后的画面版本。
- REVIEW 修改记录。
- 未解决的问题。
- 多个可能版本。

目标不是一次生成完整章节，而是保存作者脑中的具体镜头。

* 协作流程

1. 用户提出一个画面、动作、人物关系或冲突瞬间。
2. 通过讨论逐步明确画面。
3. AI 根据讨论落地场景文本。
4. 用户通过 REVIEW 反馈调整。
5. 成熟场景长期保存，等待未来组成章节。

* REVIEW 标记

沿用现有 REVIEW 方法：

- # REVIEW: 修改意见。
- # DELETE: 删除建议。
- # KEEP: 保留内容。
- # QUESTION: 因果或逻辑问题。
- # GLOBAL: 影响整体方向的问题。

* 章节生成

多个场景成熟后，再讨论：

- 是否属于同一章节。
- 场景顺序。
- 是否需要补充连接场景。
- 是否删除部分场景。

只有镜头链成熟后，才进入 manuscript 正文阶段。
